# Claude Development Rules

## Project purpose

LocalConvert is a cross-platform, local-only file conversion and compression application.

## Non-negotiable guarantees

- User files never leave the device.
- Source files are never modified.
- No conversion succeeds without output validation.
- No shell command strings are built from user input.
- Unsupported operations fail clearly.
- Correctness has priority over speed and feature count.
- All heavy work runs outside the UI thread.
- Every platform-specific behavior must be tested or documented.

## Architecture boundaries

- React handles presentation and local UI state.
- Rust owns filesystem access, jobs, processes, validation, and plugins.
- The frontend must not receive arbitrary filesystem access.
- Conversion engines are invoked only through typed Rust APIs.
- Plugins cannot bypass the job and validation systems.

## Code requirements

- Rust must pass rustfmt and clippy with warnings treated as errors.
- TypeScript strict mode is mandatory.
- Avoid `any`.
- Every error must map to a structured domain error.
- Tests are required for fixes and features.
- Temporary resources must use RAII cleanup where practical.

## Completion rules

Never state that a feature is complete unless:
- Relevant tests passed.
- The output is independently validated.
- Cross-platform implications were considered.
- Documentation was updated.

## How this repository is actually laid out

```
crates/localconvert-core/     domain contracts, job state machine, paths,
                              temp workspaces, validation framework
apps/desktop/src-tauri/       window, IPC surface, job registry/scheduler
apps/desktop/src/             React UI
apps/desktop/src/bindings/    GENERATED by ts-rs — never edit by hand
docs/                         architecture, matrix, testing, security, privacy,
                              packaging, roadmap
```

New crates arrive when the phase that needs them arrives. Do not pre-create
empty `plugin-*` crates or `packages/*` workspaces "for later".

## Rules that are enforced by code, not convention

Before changing any of these, read the test that guards them — they are
invariants, not preferences.

| Guarantee | Enforced by |
|---|---|
| Completion requires validation | `JobStatus::can_transition_to` — `Completed` is reachable only from `Validating` |
| Output never reaches the user unvalidated | `runner::commit` refuses any invalid report and deletes the staged file |
| Cleanup cannot escape the temp root | `workspace::remove_fenced` canonical containment check |
| No generic fs/shell/process IPC | `commands::tests::the_window_capability_grants_no_dangerous_permissions` |
| Frontend types cannot drift from Rust | ts-rs export + `git diff --exit-code` in CI |
| Every backend message key has a string | `apps/desktop/src/messages.test.ts` scans the Rust sources |
| No operation is advertised without a dispatch arm | `operation::tests::registered_operations_are_all_dispatchable` |
| The image route advertises only decodable formats | `operation::tests::the_image_route_advertises_only_formats_the_engine_can_read` |
| A result never overwrites its own source | `runner::commit` refuses a destination that canonicalises to an input, whatever the overwrite policy |
| No warning key reaches a user as a raw identifier | `messages.test.ts` (UI) and `text::tests::every_warning_key_has_prose` (CLI) both scan the engines |

## Commands

```bash
pnpm check          # everything CI runs
pnpm dev            # tauri dev
cargo test --workspace
```

`cargo test` regenerates `apps/desktop/src/bindings/`. Commit the result.

## Warnings are notes, not alarms

A job that wrote a verified file is a **success**, even with warnings — the UI
shows it green, and the notes sit behind a "What changed" disclosure. Only
`Failed` gets the red alert; `Cancelled` gets a quiet line.

Growth is not automatically a fault: an engine sets
`ExecutionOutput.size_growth_expected` when the target is inherently larger
(lossless image from a lossy source, JSON/XLSX from CSV, WAV/FLAC from MP3,
plain TAR), and `commit` then skips `warning.output.largerThanInput`. Adding a
route that grows by nature means setting that flag.

## Things that are deliberately absent

Marked in code with `// ponytail:` comments naming the ceiling and the upgrade
path. Grep for them before assuming something was forgotten.

- The image engine lives in `core::image_engine`, not a `plugin-image` crate.
  One engine does not need a registry and dyn dispatch; extract it when archives
  (Phase 2) give `runner`'s match two real arms.
- No HEIC/AVIF/lossy-WebP — each needs a native codec. The engine declines them
  by name; never "fall back" to another format.
- No PDF rasteriser — PDF→images and in-PDF image recompression are declined by
  name for the same reason. PDF structural ops (merge/split/rotate/metadata,
  images→PDF) are pure `lopdf` and present.
- FFmpeg is NOT bundled — media uses a system-installed FFmpeg (`media::locate`),
  never a runtime download. Absent FFmpeg declines with `ToolMissing`. Child
  processes must follow the `media.rs` runner (arg arrays, env_clear, timeout,
  cancel-kills-child); never build a shell string.
- No i18n library — one locale, a plain lookup in `messages.ts`.
- No Turborepo, no `packages/*` — one app.
- No E2E/Playwright suite yet.
